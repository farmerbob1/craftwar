# Craftwar UI Framework — UI Toolkit + Input System (implementation plan)

> Handoff plan. Read `CLAUDE.md` first — its three hard rules (sim purity, view-as-projection,
> everything through the lockstep driver) govern every step here. This document is
> self-contained: all referenced code facts below were verified against the codebase at
> commit `0316de8` (M5 complete).

## 1. Context & goal

M0–M5 are done. The entire current UI is placeholder IMGUI: `Assets/Scripts/View/HudController.cs`
(OnGUI resource bar + tech-tree command card), the drag-select rect in
`Assets/Scripts/View/SelectionController.cs` (OnGUI), and `DebugOverlay.cs` (F3, stays IMGUI).
Input is raw device polling (`Mouse.current`/`Keyboard.current`); `Assets/InputSystem_Actions.inputactions`
is the unused Unity template. Nothing blocks world clicks under the HUD. The sim has no way to
tell the UI "not enough gold" — failures are silent `continue`s.

Build the **permanent UI framework**: UI Toolkit (UXML/USS/UIDocument), theme-first, screen-stack
based, driven by the new Input System via action maps. In-game HUD is the deliverable now; the
same framework hosts menus/match setup at M8 and the minimap at M6.

**Confirmed decisions (user):**
- UI Toolkit. Clean dark placeholder theme now; extracted WC2 art becomes a second theme at M8
  as a pure skin swap (USS vars + background-images), no code changes.
- Scope: framework core + resource bar + command card + selection/unit panel + pause-menu
  screen stack + minimap frame slot + sim→UI notification channel.
- Input rebuilt on InputActions (Gameplay/Camera maps) with proper pointer-over-UI blocking.

## 2. Verified codebase facts (do not re-derive; do verify if something looks off)

- Assemblies: `Craftwar.Sim` (pure C#, `noEngineReferences: true`, integer-only, deterministic),
  `Craftwar.View` (refs Sim, Unity.InputSystem, URP; `allowUnsafeCode`; auto-references
  UnityEngine.UIElementsModule — **no new asmdef needed**), `Craftwar.Net`, `Craftwar.App`,
  `Craftwar.Import`, `Craftwar.Sim.Tests`.
- `ISimHost` is defined in `Assets/Scripts/View/UnitViewPool.cs`: `{ GameSim Sim; float Alpha;
  int[] PrevPixX/PrevPixY; void SubmitCommand(in GameCommand); }`. Implemented by
  `Assets/Scripts/App/GameLoopRunner.cs` (fixed 50 Hz accumulator loop, max 8 catch-up ticks,
  drains `Sim.State.TileChanges` into `PendingTileChanges` per tick).
- `GameBootstrap.Start()` (`Assets/Scripts/App/GameBootstrap.cs`) creates everything at runtime
  via `AddComponent` + `Init(...)` injection; no UI prefabs. Its `LateUpdate` drains
  `runner.PendingTileChanges` into `tilemapView`. Scene is generated by
  `Craftwar.EditorTools.ProjectBootstrap` (idempotent; extend it, same pattern).
- Selection lives in `UnitViewPool.Selected` (`HashSet<uint>` of `UnitId.Packed`); commands
  carry up to `GameCommand.MaxSelection = 18` ids. `HudController.PendingBuildType` (ushort)
  is the placement-mode handshake read by `SelectionController` and `BuildPlacementGhost`.
- Command card logic in `HudController.DrawCommandCard`: worker selected → `TechTree.WorkerBuildings(race)`
  gated by `sim.CanProduce`; building selected → `TechTree.Trains` (+`TrainSubstitute`),
  `TechTree.UpgradesTo` gated by `CanUpgradeBuildingTo`, `TechTree.Research` gated by
  `CanResearchAt`; busy building (UnderConstruction / `BuildType != 0` / `ResearchId != 0`)
  shows Cancel. Commands submitted with `SelectionCount = 1` + the building's packed id.
- Unit data for panels: `Unit { Hp, Order, BuildType (1-based), TrainTicks (countdown),
  ResearchId (1-based), RallyX/Y, CarryType, Flags (UnderConstruction/Building/Alive) }`.
  `UnitTypeData` has costs/BuildTime/Armor/damage/Range/Sight/BoxW/H. `GameSim` exposes
  `EffectiveStrength/Pierce/Armor/Range/Sight`. **No mana, no kill counts, single-slot queue** —
  do not build UI for those. Progress total: sim-internal `BuildTicks(BuildTime)` (private —
  expose as `public static ushort BuildTicksFor(int buildTime)`).
- Silent-failure sites to instrument (see §6): `GameSim.Economy.cs` `ApplyEconomyCommand`
  (Train cost/food checks, Build gate, plus `TickBuilderWalk` arrival failure),
  `GameSim.Tech.cs` `ApplyResearchCommand` cost check, `TickProduction` completions,
  `TickHarvest` mine collapse, damage application in `GameSim.Combat.cs`.
- `GameState.TileChanges` is the existing "derived output, not hashed" pattern — copy it exactly.
- Input System 1.19 is the exclusive handler (`activeInputHandler: 1`). No EventSystem in scene.
- Determinism suite (`Craftwar.Sim.Tests`, EditMode) must stay green after every phase that
  touches Sim. `SimPurityTests` source-scans Sim for engine references.

## 3. Core architecture

### One UIDocument, one panel, four layers
Root UXML (`HudScreen.uxml` hosts only the HUD; the document root is built by `UIManager`):

```
#root (absolute 0/0/0/0, picking-mode Ignore)
 ├── #layer-hud       resource strip, sidebar, command card
 ├── #layer-screens   screen-stack host (pause menu; later main menu/options)
 ├── #layer-overlay   drag-select rect, future tooltips (picking Ignore)
 └── #layer-notify    notification feed (picking Ignore)
```

One PanelSettings, one `panel.Pick` call for pointer blocking, z-order by child index.
`BuildPlacementGhost` stays a world-space SpriteRenderer (not UI Toolkit).

### One MonoBehaviour, plain-C# views
Exactly one new MonoBehaviour: **`UIManager`** (adds its own `UIDocument`, assigns PanelSettings
+ root from the catalog). Everything else is `sealed` plain C# classes receiving a
`VisualElement` subtree + deps via constructor/`Init` — matching sim style. `UIManager.Update()`
ticks the screen stack and refreshes `UIState.PointerOverUI`.

### UIAssetCatalog
`Assets/UI/Resources/UIAssetCatalog.asset` (ScriptableObject: PanelSettings, theme stylesheets,
every VisualTreeAsset). `UIManager` does one `Resources.Load<UIAssetCatalog>("UIAssetCatalog")`.
Created idempotently by new `ProjectBootstrap.EnsureUiAssets()` (`Craftwar/Setup/Ensure UI Assets`).

### UIState (replaces HudController as the shared handshake object)
```csharp
namespace Craftwar.View
{
    /// <summary>Frame-rate UI/input state shared between world input and panels. View-only.</summary>
    public sealed class UIState
    {
        public ushort PendingBuildType;   // nonzero while placing (was HudController.PendingBuildType)
        public bool ModalOpen;            // a modal stack screen blocks world input
        public bool PointerOverUI;        // refreshed each frame by UIManager
        public readonly SelectionState Selection = new();
    }
    /// <summary>Selection with a version counter for dirty-checking.</summary>
    public sealed class SelectionState
    {
        public readonly HashSet<uint> Ids = new();
        public int Version { get; private set; }
        public void Clear() { if (Ids.Count > 0) { Ids.Clear(); Version++; } }
        public bool Add(uint packed) { if (Ids.Add(packed)) { Version++; return true; } return false; }
        public void SetSingle(uint packed) { Ids.Clear(); Ids.Add(packed); Version++; }
    }
}
```
`UnitViewPool.Selected` is replaced by an injected `SelectionState` (pool only iterates it for
selection boxes — mechanical change).

### Runtime event dispatch (Unity 6.x)
With Input System active and **no** scene EventSystem, UI Toolkit's built-in runtime dispatch
drives the panel — `UIDocument + PanelSettings` is sufficient. **Verify clicks in Phase 1 before
building on it.** Fallback if 6.5 regresses: add `EventSystem + InputSystemUIInputModule` in
bootstrap. Never mix both paths.

## 5. Component specs

**`UIManager : MonoBehaviour`** — `Init(ISimHost host, UIState state)`; owns UIDocument, screen
stack, catalog. `IsPointerOverUI(Vector2 screenPosBottomLeft)`: flip Y (`Screen.height - y`),
`RuntimePanelUtils.ScreenToPanel`, `panel.Pick(...) != null`; guard `panel == null` on early
frames. `Push/Pop` delegate to `UIScreenStack`; `HandleSimEvents(List<SimEvent>)` fans out to
notification feed + command-card dirty check.

**`UIScreen` / `UIScreenStack`** — abstract screen: `IsModal`, `Attach(layerRoot, assets)`,
`OnPush/OnPop/OnFocus/OnBlur/Tick`, `bool HandleEscape()`. Stack: `Push/Pop/Top/AnyModal`
(mirrored to `UIState.ModalOpen`), `Tick()`, `RouteEscape()` (top-down). `HudScreen` is the
permanent bottom entry, never popped.

**`HudScreen`** — WC2-shaped layout: top resource strip; left sidebar = minimap frame (top) /
selection panel (middle) / 3×3 command card (bottom); notifications bottom-center of viewport.
Constructs and ticks child views.

**`ResourcePanelView`** — caches last-written ints (Gold/Lumber/Oil/FoodUsed/FoodMax); writes
`Label.text` only on change. Food gets a warn class when `FoodUsed >= FoodMax`.

**`CommandCardModel`** (plain, no VisualElements — unit-testable) — ports `DrawCommandCard`
logic into 9 slots:
```csharp
public struct CommandSlot
{
    public CommandSlotKind Kind;   // None, Build, Train, UpgradeTo, Research, Cancel, BuildMenuToggle
    public ushort Param;           // UnitTypeId / UpgradeId
    public int Gold, Lumber, Oil;  // display costs
    public bool Enabled;           // affordability, recomputed per frame
    public int BuildingSlot;       // receiving unit slot (-1 for worker placement)
}
public sealed class CommandCardModel
{
    public readonly CommandSlot[] Slots = new CommandSlot[9];
    public bool AdvancedPage;      // worker Basic/Advanced page toggle (10 buildings > 9 slots, WC2-style)
    public ulong StructureHash;
    public void Rebuild(GameSim sim, SelectionState sel);
    public void RefreshEnabled(GameSim sim);   // int compares only
}
```
`StructureHash` = selection `Version` ⊕ `Players[0].Researched` ⊕ per-selected building
`(packedId, Flags & (Building|UnderConstruction), BuildType, ResearchId)` — deliberately
**excludes `TrainTicks`**. Rebuild when hash changes, when drained SimEvents include
Construction/Upgrade/ResearchComplete or a local unit death, plus a 2 Hz safety re-check.

**`CommandCardView`** — 9 slots pre-instantiated from `CommandButton.uxml` once (visibility +
class toggles only, never churn). Placeholder art: colored box + 2-letter initials + hotkey
letter (`.command-button__key`). Activation (click or hotkey): Build → `ui.PendingBuildType =
Param` (existing ghost/placement flow); Train/UpgradeTo → `CommandOp.Train`; Research →
`CommandOp.Research`; Cancel → `CommandOp.Cancel` — same single-building command construction
as `HudController.Submit` (SelectionCount=1, packed building id). Busy buildings render
"Training Footman… 43%" from `TrainTicks`.

**`SelectionPanelView` + `UnitTileView`** — three modes by selection content:
- Single unit: name (`UnitNames`), HP `x/y` + bar (color thresholds 100/50/25% → green/yellow/red
  vars), Armor/Damage/Range/Sight via `UnitTypeData` + `EffectiveStrength/Pierce/Armor/Range`,
  carry indicator when `CarryType != None`.
- Multi (2–18): fixed pool of `GameCommand.MaxSelection` tiles (`UnitTile.uxml` clones);
  tile = initials box + mini HP bar; click → `ui.Selection.SetSingle(packed)` (sub-select).
  Extra tiles `display:none`.
- Building: name/HP; UnderConstruction → progress bar `TrainTicks / BuildTicksFor(BuildTime)`;
  training/researching → label + progress; idle → rally coords display. Portraits = initials
  boxes until M8.

**`NotificationFeedView`** — last ~4 lines for the local player from drained SimEvents; timed
fade via `schedule.Execute` class toggle; `CommandDenied` also flashes the short resource red
in the resource strip.

**`MinimapFrameView`** — styled empty frame reserving the sidebar top slot; pickable (blocks
clicks behind it); exposes `public VisualElement Content { get; }` for M6.

**`DragSelectOverlayView`** — one absolute element in `#layer-overlay` (picking Ignore);
`Show(Vector2 panelA, Vector2 panelB)` / `Hide()`. Replaces `SelectionController.OnGUI`.

**`PauseMenuScreen : UIScreen`** (`IsModal = true`) — Resume, disabled Options/Save placeholders,
Quit (`Application.Quit`). `OnPush` → `runner.SetPaused(true)`; `OnPop` → unpause;
`HandleEscape()` pops itself. Doc comment: single-player pauses the accumulator; networked
lockstep (M10) cannot pause — branch on driver type then.

**`UnitNames`** — static `string[]` of spaced display names per `UnitTypeId`/`UpgradeId`, built
once (absorbs `HudController.NameOf`). Cost strings baked at card rebuild only.

## 6. SimEvent channel (the only Craftwar.Sim change — determinism-critical)

`Assets/Scripts/Sim/Core/SimEvent.cs` (engine-free):
```csharp
namespace Craftwar.Sim
{
    public enum SimEventKind : byte
    {
        None = 0,
        CommandDenied,        // A = (ushort)DenyReason, B = command Param
        TrainComplete,        // B = trained TypeId, UnitPacked = producing building
        ResearchComplete,     // B = (ushort)UpgradeId
        ConstructionComplete, // B = TypeId, UnitPacked = building
        UpgradeComplete,      // building tier swap done; B = new TypeId
        BuildSiteBlocked,
        UnderAttack,          // B = victim TypeId, UnitPacked = victim (throttled)
        MineCollapsed,
    }
    public enum DenyReason : byte
    { None = 0, NotEnoughGold, NotEnoughLumber, NotEnoughOil, NotEnoughFood, TechUnavailable, Busy, SiteBlocked }

    /// <summary>Derived per-tick output for the presentation layer, exactly like
    /// GameState.TileChanges: written by the sim from state transitions, never read
    /// by the sim, never hashed. Cannot affect determinism.</summary>
    public struct SimEvent
    {
        public SimEventKind Kind;
        public byte Player;
        public ushort A, B;
        public uint UnitPacked;
    }
}
```
- `GameState`: `public readonly List<SimEvent> Events = new();` beside `TileChanges`, same
  "not hashed (derived)" doc comment. `GameSim.Advance` adds `State.Events.Clear();` beside
  `TileChanges.Clear()`. Internal `void Emit(SimEventKind, byte player, ushort a, ushort b, uint unit = 0)`.
- **Emission sites** (one `CommandDenied` per command, not per candidate building — accumulate
  the first failing `DenyReason` across the selection loop; `Busy` when all candidates occupied):

| Site | Current behavior | Event |
|---|---|---|
| `ApplyEconomyCommand` Train cost/food check | silent `continue` | `CommandDenied(NotEnoughGold/Lumber/Oil/Food or Busy)` |
| `ApplyEconomyCommand` Build gate (`CanProduce`/menu) | silent `break` | `CommandDenied(TechUnavailable)` |
| `ApplyResearchCommand` cost check | silent `continue` | `CommandDenied(...)` |
| `TickBuilderWalk` arrival failure | order dropped | `BuildSiteBlocked` (or `CommandDenied(NotEnough*)` on cost recheck fail) |
| `TickProduction` construction finish | — | `ConstructionComplete` |
| `TickProduction` research finish | — | `ResearchComplete` |
| `TickProduction` train finish / tier swap | — | `TrainComplete` / `UpgradeComplete` |
| `TickHarvest` mine exhausted → destroy | — | `MineCollapsed` (harvester's player) |
| `GameSim.Combat.cs` damage applied | — | `UnderAttack`, throttled ≤ once per 500 ticks per player via unhashed `int[] LastUnderAttackTick` on GameState |

- `GameLoopRunner`: `public readonly List<SimEvent> PendingSimEvents = new();` — `AddRange`
  in the tick loop next to the TileChanges handling. `GameBootstrap.LateUpdate` hands the batch
  to `UIManager.HandleSimEvents(...)` then clears (mirrors the existing TileChanges drain).
- **`SimEventTests.cs`**: (1) same scenario twice → identical event sequences; (2) state hash
  unaffected by events (never hashed); (3) denied train with 0 gold emits exactly one
  `CommandDenied(NotEnoughGold)`. Existing determinism + purity suites must stay green.

## 7. Input rebuild

`Assets/Input/CraftwarActions.inputactions`, generate C# class `CraftwarActions`
(namespace `Craftwar.View`):

| Map | Action | Binding |
|---|---|---|
| Gameplay | `Point` | `<Mouse>/position` (pass-through) |
| | `Select` | `<Mouse>/leftButton` (press+release for drag) |
| | `Order` | `<Mouse>/rightButton` |
| | `AdditiveModifier` | `<Keyboard>/shift` |
| | `AttackMoveModifier` | `<Keyboard>/leftCtrl` (temporary until attack-move is a card slot) |
| | `CardSlot0..8` | `q w e / a s d / z x c` (fixed 3×3 grid) |
| | `CancelOrMenu` | `<Keyboard>/escape` |
| | `ToggleDebug` | `<Keyboard>/f3` |
| Camera | `Pan` | 2D composite on **arrow keys** |
| | `Zoom` | `<Mouse>/scroll/y` |

**Decisions:** grid hotkeys (QWE/ASD/ZXC ↔ slots 0–8), not per-command WC2 letters — no
conflict management for a dynamic card; WC2 letters become a data swap later (card already
renders a hotkey label per slot). **WASD camera pan is removed** (freed for hotkeys; arrows +
edge scroll is WC2-faithful) — deliberate feel change, flag it in the commit message; it's a
data rebind away from reverting after this phase. Old `A+click` attack-move chord deleted
(replaced by Ctrl+click for now).

**`InputRouter : MonoBehaviour`** — owns `CraftwarActions`; exposes typed events
(`OnSelectPressed/Released`, `OnOrderPressed`, `OnCardSlot(int)`, `OnEscape`) + polled values
(`Pan`, `Zoom`, `PointerPosition`, `Additive`, `AttackMove`). Disables Gameplay+Camera maps
while `UIState.ModalOpen`. Escape routing: `PendingBuildType != 0` → clear it; else card
advanced page open → back; else `stack.RouteEscape()`; else push `PauseMenuScreen`.
`OnSelectPressed` is not forwarded to world input when `UIState.PointerOverUI`.

**Pointer blocking rules** (in `WorldInputController`):
- Press starting over UI → no world drag begins (UI handles the click natively).
- A drag that started in the world stays a world drag even if released over UI.
- Right-click and placement clicks over UI are swallowed.
- Picking discipline: every layer container and decorative element is `picking-mode="Ignore"`
  in UXML; only real panels are pickable — so `panel.Pick` is null over open battlefield.

**`WorldInputController`** — `SelectionController` renamed; consumes router events; ports
`IssueSmartOrder` / `SelectInRect` / `PlaceBuilding` **verbatim** (they are correct), swapping
`_pool.Selected` → `_ui.Selection` and `_hud.PendingBuildType` → `_ui.PendingBuildType`; drag
visuals via `DragSelectOverlayView`. New: RMB with a single own completed building selected →
`CommandOp.SetRally` at clicked tile (sim already supports it; world rally marker is M6).

**`CameraRig`** — keeps all math; reads `input.Pan`/`input.Zoom`; edge scroll still polls
`input.PointerPosition`. Gains `Init(InputRouter)`. **`DebugOverlay`** stays IMGUI; F3 arrives
via router toggling `enabled`. **`BuildPlacementGhost`** unchanged except `Init` takes `UIState`
instead of `HudController`.

## 10. Performance discipline

- Compare-then-write everywhere: cache last-written ints; touch `.text` / bar
  `style.width = Length.Percent(...)` only on change. No `$""` interpolation inside `Tick`.
- State changes via `AddToClassList`/`EnableInClassList`, not inline styles (bar widths and
  the drag rect are the exceptions).
- Fixed element pools (9 card slots, 18 unit tiles) created once at `Attach`; visibility
  toggles only. `:hover` only on card slots, menu buttons, unit tiles.
- Prefer `CloneTree(parent)` into a styled container for slots/tiles;
  `VisualTreeAsset.Instantiate()` returns a TemplateContainer wrapper — when used for
  screens/overlays, make it absolute full-screen with `pickingMode = Ignore`.

## 11. Pause (single-player)

`GameLoopRunner`: `public bool Paused { get; private set; }` +
`SetPaused(bool)` (zero the accumulator on pause; early-return in `Update` while paused).
Sim untouched → hash unaffected; `Alpha` freezes so units hold position; replay unaffected.
Input gated via `UIState.ModalOpen` (maps disabled).

## 13. Implementation phases — each leaves the game playable; commit per phase

1. **Skeleton + resource bar.** Assets/UI tree, `EnsureUiAssets`, `UIManager/UIScreen/
   UIScreenStack/UIState/HudScreen/ResourcePanelView/MinimapFrameView`, bootstrap wiring.
   Strip only the resource-bar block from `HudController` (its card stays temporarily).
   Patch old `SelectionController.Update` first line: `if (_ui.PointerOverUI && leftPressed) return;`.
   **Verify:** play mode — resource strip live-updates as peons deposit; clicking any HUD area
   does NOT select units behind it (this test guards the picking-mode-leak risk); minimap frame
   visible; EditMode suite green (no sim change).
2. **Command card.** `CommandCardModel/View`, `CommandButton.uxml`, `UnitNames`;
   `UIState.PendingBuildType` authoritative.
   **Verify:** worker Basic/Advanced pages; place Farm (ghost, placement, RMB cancel); train
   Footman; hall tier upgrade; smithy research; Cancel refunds; greying when poor; card clicks
   never leak to world.
3. **Selection panel; delete HudController.** `SelectionPanelView/UnitTileView/UnitTile.uxml`;
   expose `GameSim.BuildTicksFor`; delete `HudController.cs`.
   **Verify:** single/multi/building panel modes; tile click sub-selects; construction/training/
   research progress bars advance; 18-tile cap.
4. **SimEvent channel + notifications.** §6 in full + `NotificationFeedView` + `SimEventTests`.
   **Verify:** EditMode determinism suite green (critical — this touches Sim); new tests green;
   0-gold train shows "Not enough gold"; research-complete line appears; card rebuilds when a
   barracks finishes.
5. **Input rebuild.** Actions asset + generated class, `InputRouter`, `WorldInputController`
   (delete `SelectionController`), `CameraRig` refactor, `DragSelectOverlayView`, grid hotkeys,
   F3 routing, rally RMB.
   **Verify (manual checklist):** drag select + shift additive; smart orders (attack/harvest/
   repair/move); Ctrl+click attack-move; QWE/ASD/ZXC activate card slots; arrows/edge/zoom
   camera; placement flow; drag rect renders in UI layer; press starting over HUD never drags.
6. **Pause menu.** `PauseMenuScreen` + `menus.uss` + `SetPaused` + Escape chain.

## 14. Risks & gotchas

- **No-EventSystem runtime dispatch**: verify clicks Phase 1 before anything depends on it;
  fallback = `EventSystem + InputSystemUIInputModule`; never run both dispatch paths.
- **Picking leaks**: one forgotten pickable full-screen element makes the whole viewport
  "over UI" and kills world input. Phase 1's click-through test + UXML review guard this.
- **Coordinates**: `RuntimePanelUtils.ScreenToPanel` does NOT flip Y — flip manually
  (`Screen.height - y`). `panel` is null before first layout — guard.
- **Sim purity**: `SimEvent.cs` must stay engine-free; never hash or branch sim logic on
  `Events` / `LastUnderAttackTick`. `SimPurityTests` + determinism suite are tripwires.
- **Allocs**: no per-frame string building; UI Toolkit Debugger + profiler pass at Phase 3.
- **`GameCommand.MaxSelection`** stays the selection cap; size the tile pool from the constant.
- **WASD removal** is a feel change — call it out; rebindable data after Phase 5.
